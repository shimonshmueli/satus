## Morning runbook

### Step 0 — one-time prereq (only if you've never notarized this machine)

```bash
./notarize_app.sh --store-credentials
```

This prompts for an app-specific password generated at
<https://appleid.apple.com> → Sign-In and Security → App-Specific Passwords.
The Apple ID it uses is the one baked into `notarize_app.sh`:
`shimon.shmueli@outlook.com` (Team ID `66WFCS85L8`). If either of those is
wrong, edit the script first.

After this the keychain profile `ZoneKeyNotary` exists and you don't have
to do it again.

### Step 1 — notarize Pro

```bash
./notarize_app.sh --pro
```

This runs the full pipeline:

1. Release build with `SATUS_PRO` defined
2. Assemble `.app` bundle
3. Sign with your Developer ID Application identity + `Entitlements.plist`
4. Submit to Apple's notarization service
5. Wait for the result
6. Staple the ticket

Expect ~3–10 minutes total, most of it waiting on Apple's queue.

### Step 2 — notarize Free

```bash
./notarize_app.sh
```

Same pipeline without the Pro flag.

### Step 3 — verify Gatekeeper acceptance

```bash
spctl --assess --verbose ~/Applications/ZoneKey\ Pro.app
spctl --assess --verbose ~/Applications/ZoneKey.app
```

Both should report:
```
accepted
source=Notarized Developer ID
```

### Step 4 — verify Quit-from-sandbox (the main 1.1 acceptance test)

This is the feature that needed the new Apple Events entitlement. It only
matters once it's running under a real sandboxed, notarized binary.

1. Launch the notarized `ZoneKey Pro.app`.
2. Open any app you don't already have an Automation permission grant for
   (e.g. TextEdit if you've never quit it via ZoneKey).
3. In ZoneKey, right-click that app → **Quit**.
4. **Expected:** macOS shows an Automation permission dialog asking if
   ZoneKey can control TextEdit. Approve.
5. Target app quits.
6. Right-click → Quit on the same app a second time. **Expected:** silent
   quit, no prompt (the grant is persisted).

If step 4 fails (no prompt, no quit), the entitlement isn't being applied —
check that `codesign -d --entitlements - ~/Applications/ZoneKey\ Pro.app`
lists `com.apple.security.temporary-exception.apple-events`.

### Step 5 — push to GitHub

Only after the notarized .app has been verified in Step 4. (Don't push
broken code as the latest tag.)

```bash
git push origin main
```

11 commits will go up.

### Step 6 — optional: DMG for distribution

```bash
./notarize_app.sh --pro --dmg
./notarize_app.sh --dmg
```

This produces signed, notarized .dmg files ready to upload to the website
or GitHub Releases.

## Known issues parked overnight

- **Ollama slow / appears hung.** Local 3B model on Apple Silicon takes
  ~5 minutes for 198 apps. Status text doesn't update mid-run so it looks
  stuck. We didn't add per-batch progress yet. If you want to ship 1.1
  with the slowness visible, add a "Classifying batch i of N" status
  update to `SettingsView.runClassification` — small change.
- **Plan-doc rename.** `docs/llm-tagging-plan.md` → `docs/autotag-plan.md`
  landed in a separate commit.
- **`Builds/` blobs.** ~134 MB of old `.xcarchive` directories are still
  tracked in git despite the `.gitignore` rule. `git rm -r --cached Builds/`
  + commit would stop new clones from receiving them. The bytes live in
  history; rewriting that needs `git filter-repo` and is a separate
  decision. Not blocking 1.1.
- **No CHANGELOG.** Optional for a website-only release; would be useful
  for a GitHub release body.

## Rollback path

If notarization fails or Step 4 surfaces a problem:

1. The previous notarized .app (1.0 build 6) is still in `Builds/` —
   you can re-distribute that while we fix.
2. To revert the working tree to the last shipped version:
   `git checkout db7983f -- Sources/ Entitlements.plist` (won't move HEAD,
   just restores files).
3. Don't push if local commits are broken; the only published thing on
   `origin/main` is the v1.0-shipping state until you `git push`.
